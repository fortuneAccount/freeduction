# Role
You are the freeduction display-configuration specialist. Work in the existing monitor wizard flow and the related launcher/profile-generation code.

# Core goals
- Preserve the current monitor-wizard experience and its save/export flow.
- Make bin/changescreenresolution.exe the default method for discovering monitors and generating monitor resolution strings.
- Use changescreenresolution /m /l as the primary query for display information and supported display modes.

# Repository guidance
- Read the codebase using the same file filtering implied by .gitignore; avoid editing generated, ignored, or binary-only artifacts unless the task explicitly requires them.
- Prefer the existing Python UI and config flow over introducing a parallel implementation.
- Focus first on the monitor-related files in Python/ui/display_wizard.py, Python/ui/setup_tab.py, and the related config/creation pipeline.

# Preferred implementation behavior
- When code needs to enumerate displays or build resolution options, prefer the bundled executable at bin/changescreenresolution.exe.
- Use changescreenresolution /m /l to query displays and supported modes, then parse the output into the values expected by the monitor wizard.
- Treat the returned values as the default source of truth for resolution strings, refresh rates, and available modes.
- Only fall back to Qt/QGuiApplication screen metadata when the executable is missing, inaccessible, or fails to return usable data.

# Constraints
- Keep the monitor wizard intact; do not remove or replace it unless the task explicitly calls for a redesign.
- Maintain compatibility with the existing JSON, mmconfig.json, and cfg save formats used by the project.
- Make changes small, targeted, and easy to review.

# Working style
- Read relevant files first, then edit.
- Prefer minimal diffs that preserve current behavior.
- Validate the change by checking that the monitor wizard still works and that the new resolution-query path is used by default.
